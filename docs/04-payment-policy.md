# ParityPay 결제 정책서 (DOC-04)

> **에이전트 지침**
> - **읽는 시점**: 금액·상태·취소·오류 응답과 관련된 코드를 쓸 때 반드시.
> - **이 문서가 정하는 것**: 업무 규칙(`BR-`), 멱등성 정책, 취소 가능액 계산, 오류 코드, 금융 불변조건(`INV-`).
> - **강제 규칙**: 여기 규칙과 다른 동작을 구현하지 않습니다. 규칙이 없는 상황을 만나면 임의로 정하지 말고 이 문서에 규칙을 추가할지 사용자에게 확인합니다. 오류 코드는 §10 표에 있는 것만 사용합니다.

## 1. 공통 정책

### BR-001 금액

- MVP의 통화는 `KRW` 하나입니다.
- 금액은 원 단위 양의 정수 `BIGINT`로 저장합니다.
- 요청 금액은 1원 이상이어야 하며 시스템 한도 이하여야 합니다.
- 금액 계산에 `float` 또는 `double`을 사용하지 않습니다.
- 서로 다른 통화를 하나의 원장 거래에 포함하지 않습니다.

### BR-002 시간과 식별자

- 서버 시간은 UTC로 저장하고 UI에서 사용자의 시간대로 표시합니다.
- 외부에 노출되는 ID는 추측하기 어려운 UUIDv7 또는 동등한 식별자를 사용합니다.
- 업무 거래에는 `createdAt`, 최종 변경 시각과 주요 상태 확정 시각을 별도로 저장합니다.

## 2. 지갑 정책

- 사용자·통화별 활성 지갑은 하나만 허용합니다.
- 지갑 상태는 `ACTIVE`, `SUSPENDED`, `CLOSED`입니다.
- `SUSPENDED`는 조회와 환불 수령은 허용하지만 신규 충전·결제·송금을 금지할 수 있습니다.
- `CLOSED`는 신규 거래를 허용하지 않으며 잔액 0과 미결 거래 없음이 선행되어야 합니다.
- 가용 잔액은 신규 지출 가능 금액, 보류 잔액은 처리 중 잠긴 금액입니다.
- 잔액 스냅샷은 원장의 파생 데이터이며 진실의 원천이 아닙니다.

## 3. 충전 정책

- 충전은 본인 소유로 확인된 활성 Mock Bank 계좌에서만 가능합니다.
- 충전 요청에는 `Idempotency-Key`가 필수입니다.
- 계좌 출금 결과가 명시적 실패이면 충전을 `FAILED`로 확정합니다.
- 외부 결과를 모르면 `UNKNOWN`으로 보존하고 조회 API로 확정합니다.
- 충전 성공 후에는 은행예치금 자산 차변과 사용자 페이머니 부채 대변을 기록합니다.
- 성공한 충전을 취소할 때 원장 원문을 수정하지 않고 반대 분개를 추가합니다.
- 일일·월간 충전 한도는 설정값으로 관리하고 평가 결과를 저장합니다.

## 4. 결제 정책

- 결제는 활성 지갑, 유효한 주문, 통화 일치, 충분한 가용 잔액과 한도 통과 시 요청할 수 있습니다.
- `orderId`, 사용자와 결제 시도 간 관계를 검증합니다.
- 동일 주문의 중복 결제를 막기 위한 비즈니스 유니크 키를 둡니다.
- 결제 요청 금액은 서버가 신뢰하는 주문 금액과 일치해야 합니다. 클라이언트가 보낸 금액을 그대로 신뢰하지 않습니다.
- 결제 승인 시 사용자 페이머니 부채를 차변, 판매자 지급예정금을 대변으로 기록합니다.
- 내부 원장 기반 페이머니 결제는 결제·원장·잔액·Outbox를 하나의 DB 트랜잭션으로 처리합니다.
- 외부 PG 결제는 로컬 DB와 외부기관을 하나의 원자적 트랜잭션으로 간주하지 않습니다. 요청을 먼저
  커밋(`PROCESSING`)하고 외부를 호출한 뒤 결과를 별도 트랜잭션에 확정합니다. 커밋이 먼저인 이유는,
  그것이 없으면 프로세스가 죽었을 때 "청구했는지조차" 알 수 없기 때문입니다.
- 외부 PG 결제의 환불은 결제한 곳으로 돌아갑니다(JE-014). 지갑에 페이머니를 지급하지 않습니다.
  그렇게 하면 사용자는 카드 청구를 진 채 페이머니를 받고, 우리 원장에는 부채가 두 번 생깁니다.
- 환불 결과가 불명확하면 예약한 취소 금액을 **풀지 않습니다.** 풀면 이미 나간 환불을 다시 보낼 수
  있게 됩니다. 조회로 확정될 때까지 잠가 둡니다.
- 외부 PG 결제는 지갑 잔액을 건드리지 않습니다. 돈이 지갑에서 나가지 않았습니다. 원장은 PG 미수금
  자산과 판매자 지급예정금 부채를 함께 늘립니다(JE-013).
- 외부 호출이 응답 없이 끝나면 실패가 아니라 `UNKNOWN`입니다. API는 4xx·5xx가 아니라 202와 조회
  위치를 돌려줍니다. 실패로 답하면 클라이언트가 재시도해 이중 청구를 만듭니다.

## 5. 멱등성 정책

### 키 범위

`principalId + operation + Idempotency-Key`

### 처리 규칙

1. 최초 키는 `PROCESSING` 레코드를 생성하고 요청 본문의 정규화 해시를 저장합니다.
2. 같은 키·같은 해시는 기존 처리 상태 또는 저장된 응답을 반환합니다.
3. 같은 키·다른 해시는 `409 IDEMPOTENCY_KEY_REUSED`를 반환합니다.
4. `PROCESSING`이 비정상적으로 오래 지속되면 업무 레코드와 원장을 확인해 복구합니다.
5. 키 만료 이후에도 주문·외부 참조·원장 유니크 제약으로 금액 중복을 방어합니다.
6. 멱등성 레코드 보존 기간은 구현 시 운영 요구와 개인정보 정책을 반영해 확정합니다.

알고리즘 세부는 [09-consistency-recovery.md](09-consistency-recovery.md) §3에 있습니다.

## 6. 취소·환불 정책

- 취소는 `APPROVED` 또는 `PARTIALLY_CANCELED` 결제에만 요청할 수 있습니다.
- 취소 가능액은 `approvedAmount - completedCancellationAmount - processingCancellationAmount`입니다.
- 요청액이 취소 가능액을 초과하면 `409 CANCELLATION_AMOUNT_EXCEEDED`입니다.
- 전액 취소 완료 시 결제는 `CANCELED`, 일부 완료 시 `PARTIALLY_CANCELED`입니다.
- 취소는 원결제를 참조하는 독립 Aggregate이며 별도의 멱등성 키를 사용합니다.
- 취소 성공 시 판매자 지급예정금 차변, 사용자 페이머니 부채 대변을 기록합니다.
- 이미 정산된 결제의 취소는 판매자 미수금 또는 다음 정산 차감으로 처리하며 자동 삭제하지 않습니다.
- 외부 취소 응답 유실 시 재취소보다 상태 조회를 우선합니다.

## 7. 송금·출금 정책

- 송금 출발·도착 지갑은 활성 상태이고 통화가 같아야 합니다.
- 자기 자신에게 송금할 수 없습니다.
- 하나의 원장 거래에 출발 사용자 부채 차변과 도착 사용자 부채 대변을 기록합니다.
- 출금은 사용자 페이머니 부채 감소와 은행예치금 자산 감소를 기록합니다.
- 외부 이체 결과가 불명확하면 `UNKNOWN`으로 두고 같은 외부 키로 조회합니다.
- 충전 직후 전액 송금·출금 등 위험 규칙에 따라 추가 인증 또는 차단할 수 있습니다.

## 8. 정산 정책

- 결제 승인 즉시 판매자에게 지급하지 않습니다.
- 주문 구매확정 또는 정해진 지급 가능 조건 충족 후 `ELIGIBLE`로 전환합니다.
- 정산금액은 `승인액 - 취소액 - 플랫폼 수수료 - 기타 조정액`입니다.
- 동일 결제 금액은 여러 정산 항목에 중복 포함되지 않습니다.
- 분쟁, 위험 탐지, 계좌 오류 또는 법적 보류 사유가 있으면 `HELD`로 전환합니다.
- 지급 성공 응답 유실 시 재지급보다 외부 지급 상태 조회와 대사를 먼저 수행합니다.
- 지급 완료 이후 오류는 기존 정산을 수정하지 않고 조정 항목과 보정 분개로 해결합니다.

## 9. 대사 정책

- 내부 결제, 원장, Mock PG, Mock Bank와 정산 지급 기록을 정기적으로 비교합니다.
- 차이는 내부에만 존재, 외부에만 존재, 상태 불일치, 금액 불일치, 중복과 원장 누락으로 분류합니다.
- 단순 지연으로 설명되는 차이는 다음 대사까지 보류할 수 있습니다.
- 금액 불일치와 외부에만 존재하는 승인은 자동 보정하지 않습니다.
- 운영자 보정은 원거래, 외부 근거, 승인자와 사유를 참조하는 보정 원장으로 수행합니다.

## 10. 오류와 사용자 응답 정책

| 상황 | HTTP | 코드 | 사용자 메시지 원칙 |
|---|---:|---|---|
| 입력 금액 오류 | 400 | INVALID_AMOUNT | 수정 가능한 입력을 알려줍니다. |
| 잔액 부족 | 409 | INSUFFICIENT_BALANCE | 현재 잔액을 과도하게 노출하지 않습니다. |
| 멱등 키 재사용 | 409 | IDEMPOTENCY_KEY_REUSED | 새 키 또는 기존 요청 확인을 안내합니다. |
| 허용되지 않은 상태 | 409 | INVALID_STATE_TRANSITION | 현재 상태와 가능한 행동을 제공합니다. |
| 외부 결과 불명확 | 202 | RESULT_PENDING | 실패로 단정하지 않고 조회 위치를 제공합니다. |
| 한도 초과 | 422 | LIMIT_EXCEEDED | 한도 유형과 재시도 가능 시점을 제공합니다. |
| 위험 차단 | 403 | RISK_BLOCKED | 내부 탐지 규칙 상세를 노출하지 않습니다. |
| 서버 오류 | 500 | INTERNAL_ERROR | 거래 식별자를 제공하고 내부 정보를 숨깁니다. |

예외를 스택트레이스째 응답에 노출하지 않습니다. 응답에는 `traceId`를 포함합니다.

## 11. 금융 불변조건

- `INV-001`: POSTED 원장 거래의 차변 합계와 대변 합계가 같습니다.
- `INV-002`: 원장 항목 금액은 0보다 큽니다.
- `INV-003`: 지갑 가용 잔액은 0 이상입니다.
- `INV-004`: 동일 업무 참조의 금융 효과는 한 번만 반영됩니다.
- `INV-005`: 취소 완료액과 처리 중 금액 합계는 승인액 이하입니다.
- `INV-006`: 확정 원장 항목은 수정·삭제되지 않습니다.
- `INV-007`: 하나의 원장 거래는 하나의 통화만 사용합니다.
- `INV-008`: 정산 항목의 순액 합계는 정산 헤더 순액과 같습니다.
- `INV-009`: 지급 완료 정산은 외부 지급 참조를 가집니다.
- `INV-010`: 잔액 스냅샷은 동일 컷오프의 원장 계산값과 일치합니다.
