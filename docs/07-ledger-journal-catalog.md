# ParityPay 원장 설계서와 분개 카탈로그 (DOC-07)

> **에이전트 지침**
> - **읽는 시점**: 금액이 움직이는 코드를 쓸 때 항상. 새 업무를 추가할 때는 먼저 여기에 분개(`JE-`)를 정의합니다.
> - **이 문서가 정하는 것**: 계정 체계, 원장 데이터 모델, 표준 분개, 잔액 계산식, 전기 절차.
> - **강제 규칙**: 카탈로그에 없는 분개를 코드에서 만들지 않습니다. 모든 분개는 차변 합계 = 대변 합계이며 각 항목 금액 > 0입니다. POSTED 원장은 어떤 경로로도 UPDATE·DELETE하지 않습니다. 잔액 조회는 `wallet_balance`를 쓰되, 진실은 원장입니다.

## 1. 목적

원장은 ParityPay에서 돈의 진실을 기록하는 단일 기준입니다. `wallet_balance`는 빠른 조회를 위한 스냅샷이며 원장으로부터 재구축 가능해야 합니다.

## 2. 회계 모델

모든 POSTED 원장 거래는 다음 조건을 만족합니다.

```text
같은 transactionId·currency의 Debit 합계 = Credit 합계
모든 entry amount > 0
```

이 문서에서 차변·대변은 ParityPay 법인의 관점입니다.

## 4. 원장 데이터 모델

```text
LedgerAccount
- accountId, accountCode, ownerType, ownerId
- accountClass, normalBalance, currency, status

LedgerTransaction
- transactionId, transactionType
- referenceType, referenceId, currency
- status(DRAFT, POSTED, REVERSED)
- idempotencyKey, effectiveAt, createdAt

LedgerEntry
- entryId, transactionId, accountId
- direction(DEBIT, CREDIT), amount, createdAt
```

- `referenceType + referenceId + transactionType`에 업무상 유니크 제약을 둡니다. 이것이 `INV-004`의 최종 방어선입니다.
- POSTED 이후 원문 변경을 애플리케이션과 DB 권한으로 막습니다.
- `REVERSED`는 원거래를 수정했다는 뜻이 아니라 별도 역분개가 연결되었음을 나타냅니다.
- 원거래와 역분개는 `reversal_of_transaction_id`로 연결합니다.

### JE-012 운영 보정

보정은 고정 분개 하나가 아니라 근거에 따라 달라집니다. 다음을 필수로 기록합니다.

- 원거래와 외부 근거
- 오류 원인과 영향 금액
- 차변·대변 계정 선택 근거
- 요청자·승인자
- 대사 불일치 ID와 감사 로그 ID

정산 조정 계정은 차이를 숨기는 영구 계정이 아니며, 해소 계획과 만료 경보가 필요합니다.

## 6. 잔액 계산

사용자 페이머니 부채 계정은 Credit 정상 잔액입니다.

```text
ledgerBalance = sum(CREDIT entries) - sum(DEBIT entries)
```

가용 잔액과 원장 잔액이 다른 경우는 보류금이 존재할 때뿐입니다.

```text
availableBalance + pendingBalance = ledgerBalance
```

업무 모델에 따라 보류금을 별도 원장 계정으로 전기하면 계산식과 계정 이동을 명시적으로 조정합니다.

## 7. 전기 절차

`JournalFactory`와 원장 포트 구현은 이 순서를 따릅니다.

1. 업무 참조에 대한 기존 POSTED 거래를 조회합니다.
2. `JournalFactory`가 계정과 항목을 생성합니다.
3. 양수 금액, 단일 통화와 계정 상태를 검증합니다.
4. 차변·대변 합계를 검증합니다.
5. LedgerTransaction과 Entry를 저장합니다.
6. 상태를 POSTED로 확정하고 잔액 스냅샷을 갱신합니다.
7. 같은 트랜잭션에 Outbox 이벤트를 저장합니다.

## 8. 원장 운영 통제

- 원장 테이블의 UPDATE·DELETE 권한을 애플리케이션 역할에서 제한합니다.
- 변경 불가 트리거 사용 여부는 운영 복잡성과 테스트 후 결정합니다.
- 일별로 거래별 균형, 계정별 잔액과 지갑 스냅샷을 검증합니다.
- 대량 재구축은 컷오프와 마지막 처리 Entry ID를 기록합니다.
- 보정 분개는 일반 사용자 API에서 생성할 수 없습니다.
- 원장 내역은 업무 데이터 보존 기간보다 짧게 삭제하지 않습니다.

## 9. 테스트 불변조건

원장 관련 변경에는 아래 테스트가 함께 있어야 합니다.

- 모든 카탈로그 분개의 차변과 대변이 같습니다.
- 역분개와 원분개의 순효과가 0입니다.
- 무작위 충전·결제·취소·송금 시퀀스 후 시스템 자산과 부채가 맞습니다.
- 원장 재생으로 계산한 사용자 잔액이 스냅샷과 같습니다.
- 같은 참조의 분개 생성 요청을 반복해도 POSTED 거래는 한 건입니다.
