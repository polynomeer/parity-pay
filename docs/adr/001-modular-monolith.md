# ADR-001 모듈러 모놀리스로 시작

- Status: Accepted
- Decided: 2026-09-06
- Date: 2026-09-03

> **에이전트 영향**: 새 기능을 별도 서비스로 분리하지 않습니다. `modules/` 아래 모듈로 추가하고, 모듈 간에는 공개 포트와 이벤트만 사용합니다.

## Context

결제·지갑·원장은 강한 로컬 트랜잭션으로 보호할 가치가 크며 개인 프로젝트에서 독립 서비스 운영 비용은 높습니다. 동시에 도메인 경계와 향후 분리 가능성은 보여줘야 합니다.

## Decision

하나의 저장소와 기본 배포 단위 안에 도메인 모듈을 분리합니다. 모듈 간 공개 포트와 이벤트를 사용하고 다른 모듈의 테이블 직접 쓰기를 금지합니다. 정산·대사 워커는 동일 코드베이스의 별도 실행 단위로 둘 수 있습니다.

## Alternatives

- 처음부터 마이크로서비스: 분산 트랜잭션·배포·관측 복잡성이 학습 목표를 압도합니다.
- 계층형 단일 패키지: 구현은 빠르지만 도메인 소유권과 분리 기준이 흐려집니다.

## Consequences

핵심 불변조건 구현과 테스트가 단순해집니다. 독립 확장과 장애 격리는 제한됩니다. 모듈 경계를 자동 검사하지 않으면 시간이 지나며 결합될 수 있습니다.

## Validation

ArchUnit으로 모듈 의존성 규칙을 검사하고, 분리 후보에 대해 호출량·DB 경합·배포 요구를 측정합니다.

## Outcome — 2026-09-06

구현으로 확인했습니다. 하나의 저장소·배포 단위 안에 `shared-kernel`, `ledger`, `wallet`, `payment`,
`settlement`, `reconciliation` 모듈이 분리되어 있고, 모듈 간에는 공개 포트와 이벤트만 사용합니다.
`ModuleBoundaryTest`(ArchUnit) 12개 규칙이 다음을 강제합니다.

- 도메인 계층은 Spring·JPA·Jackson에 의존하지 않습니다.
- 각 모듈의 `adapter` 패키지는 다른 모듈에서 접근할 수 없습니다.
- `ledger`와 `reconciliation`은 업무 모듈에 의존하지 않습니다.
- `wallet`은 `payment`를 모릅니다(단방향).

**아직 하지 않은 것**: 분리 후보에 대한 호출량·DB 경합·배포 요구 측정. 서비스 분리를 검토할
근거는 부하 테스트를 운영에 가까운 환경에서 돌린 뒤에 생깁니다.
