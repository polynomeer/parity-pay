# ADR-003 이중부기·불변 원장 사용

- Status: Accepted
- Decided: 2026-09-06
- Date: 2026-09-03

> **에이전트 영향**: 잔액 컬럼만 바꾸는 코드를 쓰지 않습니다. 모든 금융 효과는 LedgerTransaction + 2개 이상의 LedgerEntry로 기록합니다.

## Context

잔액 컬럼만 변경하면 금액 변화의 근거, 시스템 전체 자산·부채와 오류 보정을 설명하기 어렵습니다.

## Decision

모든 금융 효과를 LedgerTransaction과 둘 이상의 LedgerEntry로 기록하고 차변·대변 합계를 강제합니다. POSTED 원장은 수정·삭제하지 않습니다.

## Alternatives

- 단일 거래내역과 signed amount: 단순하지만 계정 간 균형과 누락 탐지가 약합니다.
- 잔액 변경 로그만 저장: 감사와 회계적 재구축에 부족합니다.

## Consequences

대사, 감사와 잔액 재구축이 가능해집니다. 계정 체계와 분개 설계 비용이 증가하며 개발자가 회계 의미를 이해해야 합니다.

## Validation

분개 카탈로그, 속성 기반 테스트와 일별 균형 검증으로 확인합니다.

## Outcome — 2026-09-06

구현으로 확인했습니다. 모든 금융 효과가 `LedgerTransaction` + 2개 이상의 `LedgerEntry`로
기록되고, 균형은 애플리케이션(`Journal` 생성자)과 DB(지연 제약 트리거) 양쪽에서 강제됩니다.
분개 카탈로그 JE-001·003·004·007·008·009·012를 구현했고, 확정 원장의 UPDATE·DELETE가 트리거에
막히는 것을 통합 테스트로 확인했습니다.

**아직 하지 않은 것**: jqwik 속성 기반 테스트(임의 거래 시퀀스)와 일별 균형 검증 배치. 현재는
불변조건을 상시 지표(`paritypay.invariant.*`)로 관측하고 있습니다.
