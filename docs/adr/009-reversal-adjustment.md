# ADR-009 취소·보정을 새 분개로 기록

- Status: Accepted
- Decided: 2026-09-06
- Date: 2026-09-03

> **에이전트 영향**: 취소·환불·보정 구현에서 기존 원장 행을 찾아 수정하거나 삭제하지 않습니다. 원거래를 참조하는 새 역분개·보정 분개를 만듭니다.

## Context

확정 거래를 수정·삭제하면 당시 기록과 변경 이유를 증명할 수 없고 대사 시점별 결과가 달라집니다.

## Decision

취소는 원거래를 참조하는 역분개로, 오류 보정은 근거와 승인 정보를 가진 새 보정 분개로 기록합니다.

## Alternatives

- 원장 행 UPDATE: 구현은 단순하지만 감사 추적이 사라집니다.
- 원거래 DELETE 후 재생성: 외부 참조와 이벤트 연결이 깨집니다.

## Consequences

전체 변경 이력과 시점별 재구축이 가능합니다. 현재 순액을 계산할 때 원거래와 역분개를 함께 처리해야 합니다.

## Validation

원거래+역분개 순효과 0, 과거 시점 잔액 재현과 보정 감사 로그 연결을 검증합니다.

## Outcome — 2026-09-06

구현과 테스트로 확인했습니다. 취소는 원거래를 참조하는 새 분개이고, 운영 보정도 새 분개입니다.
확정 원장의 UPDATE·DELETE는 DB 트리거가 거부합니다.

구현 중 설계에 없던 경우를 하나 발견했습니다. 정산 지급이 끝난 뒤 취소가 들어오면 판매자
지급예정금(2030)이 이미 0이라 기존 취소 분개가 계정 잔액을 음수로 만듭니다. 남은 지급예정금을
확인해 부족분을 판매자 미수금(1030)으로 기록하도록 했습니다. 문서의 JE-009가 정확히 이 상황을
위한 분개였고, 어느 시점에 그것을 써야 하는지가 빠져 있었습니다.

보정 분개(JE-012)는 근거(불일치 ID)·사유·요청자·승인자를 요구하며, 요청자와 승인자가 같으면
거부합니다.
