# ADR-002 PostgreSQL을 금융 원장의 시스템 오브 레코드로 사용

- Status: Accepted
- Decided: 2026-09-06
- Date: 2026-09-03

> **에이전트 영향**: 잔액·원장의 진실을 Redis나 브로커에 저장하지 않습니다. 금융 데이터의 정합성은 DB 제약과 로컬 트랜잭션으로 보장합니다.

## Context

원장과 잔액에는 ACID 트랜잭션, 유니크·체크 제약, 잠금과 안정적인 백업·복구가 필요합니다.

## Decision

PostgreSQL을 원장과 금융 업무 데이터의 시스템 오브 레코드로 사용합니다. Redis와 브로커는 파생 데이터·전달 수단이며 금융 진실을 대체하지 않습니다.

## Alternatives

- Redis 중심 잔액: 빠르지만 내구성·감사·재구축 설명이 약합니다.
- 이벤트 저장소 단독: 재생 가능성은 좋지만 초기 운영과 쿼리 복잡성이 큽니다.
- NoSQL 원장: 확장성 이점보다 트랜잭션·제약 비용이 현재 범위에서 큽니다.

## Consequences

금융 효과를 로컬 트랜잭션과 제약으로 보호할 수 있습니다. 단일 DB 경합과 수직 확장 한계가 생길 수 있으며 이를 성능 테스트로 측정합니다.

## Validation

동일·상이 지갑 워크로드, 원장 쓰기량, 잠금 대기와 복구 절차를 측정합니다.

## Outcome — 2026-09-06

구현으로 확인했습니다. 원장·잔액·업무 데이터가 모두 PostgreSQL에 있고, 불변조건을 DB 제약과
트리거로 강제합니다(INV-001 지연 제약 트리거, INV-002·INV-005 CHECK, INV-006 append-only 트리거,
INV-009 CHECK). Redis는 아직 사용하지 않으며, 브로커(Redpanda)는 전달 수단으로만 씁니다.

**아직 하지 않은 것**: 단일 DB의 확장 한계 측정. 잠금 대기·커넥션 경합을 운영 규모 부하에서
관찰해야 이 결정의 비용을 말할 수 있습니다.
