# ParityPay 문서 지도

> **에이전트 지침**
> - **읽는 시점**: 어떤 문서를 봐야 할지 모를 때, 요구사항을 변경할 때.
> - **이 문서가 정하는 것**: 문서 간 책임 분담, 요구사항 ID 체계, 구현 후 사실로 교체해야 할 항목.
> - **강제 규칙**: 같은 정책을 두 문서에 중복 정의하지 않습니다. 정책을 바꿀 때는 아래 "단일 진실의 원천" 표에서 담당 문서 하나만 수정하고, 나머지 문서는 그 문서를 참조합니다.

## 1. 문서 목적

이 문서는 ParityPay의 요구사항, 설계, 구현, 검증 자료 사이의 관계와 작성 상태를 관리하는 기준점입니다. 같은 정책을 여러 문서에 중복 정의하지 않고, 각 문서가 책임지는 결정을 명확히 합니다.

## 4. 요구사항 추적 규칙

- 기능 요구사항은 `FR-xxx`, 비기능 요구사항은 `NFR-xxx`를 사용합니다.
- 업무 규칙은 `BR-xxx`, 불변조건은 `INV-xxx`를 사용합니다.
- 테스트는 `T-xxx`, 장애 실험은 `F-xxx`를 사용합니다.
- ADR은 `ADR-xxx`, 분개는 `JE-xxx`를 사용합니다.
- 프론트엔드 계약은 `FE-xxx`, 화면은 고객 앱 `SCR-xx`·운영 콘솔 `OPS-xx`를 사용합니다(DOC-14).
- 코드와 테스트 이름에 관련 ID를 포함하거나 테스트 메타데이터로 연결합니다.
- 커밋 footer에도 관련 ID를 남깁니다 (예: `Refs INV-005`).
- 요구사항 변경 시 영향을 받는 정책, 상태, DB, API, 이벤트, 테스트와 ADR을 함께 검토합니다.
